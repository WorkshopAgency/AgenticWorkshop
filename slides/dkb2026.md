# Model, harness, tools

The **model** generates text and proposes actions. It only knows what is in
its context window.

The **harness** (OpenCode) builds that context, applies permissions, runs the
tools the model asks for, and feeds the results back.

**Tools** read files, run commands, query databases. They run on *your
laptop*. Only the model runs at DTU or another provider.

You can swap the model and keep the project, the tools and the checks.

<!-- Sources: https://opencode.ai/v2/docs/ -->

# Skill, agent, MCP

| | What it is | Where it lives |
|---|---|---|
| **Skill** | Reusable instructions (+ scripts) for one task | `.opencode/skills/<name>/SKILL.md` |
| **Agent** | A role: instructions, model, permissions, steps | `.opencode/agents/<name>.md` |
| **MCP server** | A capability outside OpenCode, behind a standard protocol | `mcp` in `opencode.json` |

An agent decides *which* skills and tools to use. A coordinator agent can
delegate bounded jobs to specialist agents.

<!-- Sources: https://opencode.ai/v2/docs/skills/ https://opencode.ai/v2/docs/agents/ -->

# 0 · RAG: retrieval-augmented generation

```text
documents → chunk → embed → index
question  → embed → retrieve top-k chunks → prompt = question + chunks
          → model answers *from the chunks*, citing them → you check the citation
```

1. Ask Mistral **without** retrieval. Note how confident it is.
2. Read what retrieval found **before** reading the answer.
3. Ask again with `-k 3`. Check one citation with `grep`.

**Check:** retrieval can miss, and a model can ignore what it was given.

# 4 · A decision model

Many agent steps are **decisions**: misleading or not? which fix? how severe?

Instead of asking for prose and parsing it, ask a typed question and read the
**token probabilities** of the options:

| Type | Returns |
|---|---|
| yes/no | P(yes) |
| choice | a distribution over options |
| score | a distribution over levels, and its expected value |

**Check:** a token probability is not a calibrated truth. Swap the option order and see.

# 5 · Safety

A data file contains an instruction aimed at AI assistants.

1. Ask the default agent to summarise it. Read every permission prompt.
2. Repeat with `safe-analyst`, which denies the risky actions.

**Permissions are tool rules, not a sandbox.** If shell is allowed, `python -c`
can do what a denied tool could. Real isolation means a container with the
network off, or a policy-enforced sandbox such as **NVIDIA OpenShell**.

# When is a task agent-suitable?

- The result can be **checked** independently: a known number, a test, a plot you can read.
- The steps are **tool work** (read, run, query), not judgement you would not delegate to a student.
- Failure is **cheap and visible**, and the data may leave your laptop.

Not suitable: no way to check the answer, irreversible actions,
confidential data on external models.

---

# Limitations we saw today

- Confident answers without evidence (RAG, no retrieval)
- Queries that succeed on the wrong data (MCP, `NA`)
- Correct numbers, misleading plot (Simpson's paradox)
- Agents reporting success they did not check (swarm, viewers)
- Instructions hidden in data (safety)

**"Code generated" ≠ "it ran" ≠ "it is correct" ≠ "the science holds".**
